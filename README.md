# 航空貨物 進捗管理（デモ版）

国際航空輸出入業務の進捗を管理するWebアプリの**デモ版**です。
フォワーダーの担当者が、担当案件の進捗と期限をひと目で把握して、対応漏れを防ぐことを目的にしています。

- HTML / CSS / JavaScript だけで動きます（サーバー・インストール不要）
- データはブラウザの中（localStorage）に保存されます
- PC向けの画面ですが、スマホで開いても崩れずに見られます
- 最初はダミーデータ（輸出MAWB 3件・輸入MAWB 1件、HAWB 計6件）が入っています。会社名や番号はすべて架空のものです

## 開き方

### A. GitHub Pages で公開する（おすすめ）
1. リポジトリの **⚙ Settings** → 左メニューの **Pages** を開きます
2. **Build and deployment** の **Source** で **Deploy from a branch** を選びます
3. **Branch** で `main`、フォルダは `/ (root)` を選んで **Save** を押します
4. 1〜2分待ってからページを再読み込みすると、上部に公開URL（`https://dxnews-ksjp.github.io/air_cg_tracker/`）が表示されます

> 作業用ブランチ（`claude/...`）の内容は、先に `main` に取り込んでおく必要があります
> （**Pull requests** → 該当のプルリクエスト → **Merge pull request**）。

### B. パソコンで直接開く
ファイル一式をダウンロードして、`index.html` をダブルクリックするだけで動きます。
ネットにつながっていない場所でもデモできます。

## 画面と使い方

画面の上にある2つのタブで切り替えます。

### 📦 進捗管理タブ

**一覧画面（ツリー表示）**
- MAWB（親）の行の **▾ / ▸** ボタンで、配下のHAWB（子）を開いたり閉じたりできます。「すべて開く／すべて閉じる」ボタンもあります
- MAWBの行には、便情報（航空会社・便名・区間・ETD/ETA）と、配下HAWBの進捗サマリーが表示されます
  - **完了 x/y**：完了したHAWBの件数
  - **最遅**：配下のHAWBのうち、一番手前の工程（次にやる工程）
  - **遅延○件・最大○日**：遅れているHAWBの件数と、一番大きい遅延日数
- HAWBの行は、遅延していれば**赤**、期限が近ければ**黄色**の背景になります
- 特殊貨物はラベルで表示します（「危」危険品＝赤、「冷」保冷品＝青、「特」その他特殊＝紫）
- 上部のカード（遅延あり・危険品など）をクリックすると、その条件で絞り込めます。もう一度クリックすると解除されます
- 絞り込み：キーワード／輸出入／ステータス／担当者／特殊貨物／遅延
- 並べ替え：ETD順／ETA順／MAWB番号順／遅延が大きい順／更新が新しい順
- スマホでは「絞り込み・並べ替え」ボタンを押すと条件の入力欄が開きます

**登録・編集**
- 「＋ MAWB登録」「＋ HAWB登録」ボタンから登録します。MAWBの行の「＋HAWB」から登録すると、親MAWBが最初から選ばれた状態になります
- HAWBを新しく登録すると、親MAWBのETD/ETAから各工程の予定日が自動で入ります（あとから変更できます）
- MAWB番号は「3桁-8桁」の形式でチェックします。末尾のチェックデジットが合わないときは確認メッセージを出します
- MAWBを削除すると、配下のHAWBと紐づくタスクも一緒に削除されます

**HAWB詳細画面（ステータスを進める）**
- 大きな **「▶ ○○を完了にする」** ボタンを1回押すと、次の工程が完了になり、押した時刻が実績日時として記録されます
- 押し間違えたときは「↶ 1つ戻す」で取り消せます
- 実績日時を後から直したいときは「編集」から変更できます
- 工程のタイムラインで、各工程の予定日・実績日時・状態（完了／遅延／期限間近／予定）をまとめて確認できます

### ✅ タスク管理タブ

「期限切れ」「今日」「明日」の3つに分けて、やることを一覧表示します。

| 列 | 内容 |
|---|---|
| 色 | 自分チェック用のマーカー。クリックするたびに ⚪なし → 🔴要対応 → 🟡対応中 → 🟢確認済み と切り替わります |
| MAWB / HAWB | クリックすると詳細画面が開きます |
| 輸出者 / 輸入者 | 荷主（Shipper）／荷受人（Consignee） |
| タスク内容 | 工程名、または手入力したタスクの内容 |

- **工程タスク**：各工程の予定日から自動で表示されます。その工程が「次に進める工程」のときは、**[完了]** ボタンでその場で完了にできます
- **手入力タスク**：「＋ タスク追加」から、HAWBに紐づけて自由に登録できます（例：荷主にインボイスを催促）
- 完了したタスクはグレー＋取り消し線で表示されます。「完了を隠す」にチェックすると非表示になります
- 担当者で絞り込めます
- タブの横のバッジで、期限切れ・今日・明日の未完了件数がわかります

### 📄 CSV・データ管理（進捗管理タブの右上ボタン）
- **CSVエクスポート**：全データをCSVで保存します。1行がHAWB 1件で、Excelでそのまま開けます
- **CSVインポート**：取り込む前に「追加○件・更新○件」を確認できます
  - *追加・更新*（おすすめ）：MAWB番号＋HAWB番号で照合して、あれば更新・なければ追加します
  - *すべて入れ替え*：今のデータを削除してCSVの内容に入れ替えます
  - Excelで編集して保存したCSV（Shift_JIS）や、`2026/11/5` のような日付の書き方にも対応しています
- **ダミーデータに戻す**：デモ前に初期状態に戻したいときに使います

## 警告（色分け）のルール

| 表示 | 条件 |
|---|---|
| 🔴 遅延 | 予定日を過ぎても実績が入っていない工程がある |
| 🟡 期限間近 | 予定日が今日か明日で、まだ実績が入っていない工程がある |
| （表示なし） | 予定日がまだ先、または予定日が入っていない |

「期限間近」とみなす日数は `js/config.js` の `SOON_DAYS` で変えられます。

## 工程

| 区分 | 工程（この順番で進みます） |
|---|---|
| 輸出 | 受注 → ブッキング → スペース確定 → 集荷 → 貨物搬入 → 輸出通関申告 → 搭載 → 出発 → 到着確認 → 請求 → 完了 |
| 輸入 | プレアラート受領 → 到着 → 保税搬入 → D/O・書類受領 → 輸入通関申告 → 輸入許可 → 配送手配 → 配達完了 → 請求 → 完了 |

工程の名前や、予定日を自動で入れるときの日数（ETDの何日前など）は `js/config.js` の `WORKFLOWS` で変更できます。

## デモ版での注意点

- データは**そのブラウザの中だけ**に保存されます。別のPCや別のブラウザとは共有されません
- ブラウザの閲覧履歴やサイトデータを消すと、登録したデータも消えます。大事なデータはCSVで保存しておいてください
- ETD/ETAは現地時刻のまま入力・表示します（時差の変換はしていません）
- 遅延の判定は、画面を開いているパソコンの日付を基準にします

## ファイル構成（開発者向け）

```
index.html            画面の土台
css/style.css         デザイン（スマホ対応を含む）
js/
  config.js           工程定義・警告日数・色マーカーなどの設定
  util.js             日付計算・モーダルなどの共通処理
  model.js            進捗計算・遅延判定・MAWBサマリー・タスク作成（業務ロジック）
  seed.js             ダミーデータ（今日の日付を基準に作成）
  storage.js          ★データの保存・読み込み（localStorage に触るのはここだけ）
  csv.js              CSVの入出力
  views/              各画面（一覧・詳細・フォーム・タスク・データ管理）
  app.js              画面の切り替えとタブ
```

### データの持ち方
データは表ごとに分けて保存しています。データベースのテーブルにそのまま対応する形です。

| 表 | 内容 | 主な項目 |
|---|---|---|
| `mawbs` | MAWB | MAWB番号、輸出入区分、航空会社、便名、出発地、到着地、ETD、ETA |
| `hawbs` | HAWB（`mawbId` で親MAWBを参照） | HAWB番号、荷主、荷受人、個数、重量、容積重量、品名、担当者、特殊貨物、メモ、工程ごとの予定日・実績日時 |
| `manualTasks` | 手入力タスク（`hawbId` でHAWBを参照） | 日付、内容、完了フラグ |
| `taskMarks` | タスクの自分チェック色 | タスクのキー、色 |

ステータスは項目として持たずに、「先頭から続けて実績が入っている工程の数」から毎回計算しています。そのため、データの食い違いが起きません。

### サーバー・データベースへ移行するとき
- 画面側は必ず `App.repo.xxx()`（`js/storage.js`）を通してデータを読み書きしています
- `App.repo` の関数はすべて非同期（Promise）にしてあるので、中身を `fetch('/api/...')` などのAPI呼び出しに書き換えれば、画面側は変更なしで動く想定です
- 30人で同時に使う場合は、次のような対応を追加で検討してください
  - ログインと「自分の担当分」の表示（`assignee` を利用者IDに置き換える）
  - 同時編集の対策（`updatedAt` を使った更新の衝突チェック）
  - 自分チェック色の利用者ごとの保存（`taskMarks` に利用者IDを追加）
  - 担当者マスタ
